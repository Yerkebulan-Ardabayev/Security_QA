## 1. Цель

Личный сайт вопросов и ответов для подготовки к собеседованию на Security Engineer с уклоном в DevSecOps, устроенный так же, как DevOps_QA, для одного человека, Еркебулана.

## 2. Части системы

- **Движок сайта**. Копия React + Vite приложения из `~/Desktop/Projects/DevOps_QA/DevOps_Interview` (поиск, транслит, синонимы, подсветка, голосовой поиск, темы, клавиатура). Нужен, чтобы не писать интерфейс заново.
- **Исходники корпуса**. `content/NN-slug.json`, один файл на раздел. Здесь пишутся и правятся вопросы и ответы.
- **Сборщик корпуса**. `scripts/build-corpus.mjs` собирает из `content/` файл `Security_Interview.html` с объектом `var DATA` в формате DevOps-версии (плюс поле `sources`) и кладёт его в два места. HTML руками не правится.
- **Проверка ссылок**. `scripts/check-links.mjs` открывает каждую ссылку из `sources` и пишет отчёт в `_reports/links.md`.
- **Словарь синонимов и транслита по кибербезу**. Замена содержимого `synonyms.ts` и дополнение `translit.ts`, чтобы «сием» находил SIEM, «оваsп» находил OWASP, «форензика» находила forensics.
- **Тесты**. `corpus.test.ts` и `search.test.ts`, перенесённые и перенастроенные на новый корпус. Держат целостность корпуса и поиск.
- **Факт-чек**. Скрипты по образцу `DevOps_QA/_factcheck`, проверяют ответы партиями против первоисточников и пишут находки в JSON.
- **Деплой**. GitHub Actions на GitHub Pages, копия `deploy.yml`.

**DevOps_QA не меняется ни одним байтом.** Файлы копируются в новый каталог, исходный репозиторий только читается. Проверка в конце, `git -C ~/Desktop/Projects/DevOps_QA status` чистый и последний коммит тот же, что сегодня.

## 3. Вход и выход каждой части

- **content → сборщик → корпус.** Сборщик читает разделы по порядку номеров, проставляет `id` и `num` сквозной нумерацией, отказывается собирать при пустом тексте, ответе или `sources`, экранирует `};` и `</` внутри строк.
- **Корпус → движок.** Движок загружает `public/Security_Interview.html`, достаёт `DATA.categories` (список названий разделов) и `DATA.questions` (массив записей, поля ниже). Отдаёт страницу со списком разделов, вопросами и поиском.
- **Синонимы → поиск.** Поиск получает запрос пользователя, расширяет его синонимами и транслитом, ранжирует (совпадение в заголовке весит больше тела) и отдаёт список вопросов с подсветкой.
- **Корпус → тесты.** Тест проверяет, что две копии HTML идентичны, что `id` уникальны и идут подряд, что у каждого вопроса есть раздел из списка, непустой ответ и хотя бы одна ссылка на источник.
- **Корпус → факт-чек → корпус.** Факт-чек получает раздел, открывает ссылки источников, сверяет утверждения и пишет `findings-catNN.json`. Правки вносятся в корпус скриптами партий, как в DevOps-версии, прогресс в `fix-progress.json`.
- **Репозиторий → деплой.** Push в `main` запускает сборку и публикацию на Pages.

## 4. Данные

Запись вопроса, формат DevOps-версии плюс одно поле:

```json
{
  "id": 0,
  "category": "Основы безопасности",
  "text": "Чем аутентификация отличается от авторизации?",
  "answer": "<p>…</p>",
  "sources": ["https://owasp.org/…", "https://csrc.nist.gov/…"]
}
```

`sources` новое поле `[допущение]`. В DevOps-версии ссылки не вынесены отдельно, здесь отдельное поле нужно, чтобы тест мог механически проверить наличие источника, а интерфейс показал блок «Источники» под ответом.

Стиль ответа как в DevOps-версии, от первого лица, так, как отвечают вслух на собеседовании («на практике мы…»), 2–5 абзацев, при необходимости команда или конфиг в `<pre>`. Без длинных тире.

Источники ответов, только официальные и первичные.

- OWASP (Top 10, ASVS, Cheat Sheet Series), NIST (SP 800-53, 800-61, CSF 2.0), MITRE ATT&CK, CIS Benchmarks.
- Документация вендоров (Kubernetes, AWS, Docker, HashiCorp Vault, GitHub, GitLab).
- ISO/IEC 27001 и PCI DSS в части, доступной публично.
- Право РК, только действующая редакция на adilet.zan.kz (закон о персональных данных, закон об информатизации, требования к ИБ).

Поиск по словам, как в DevOps-версии. Семантический поиск не делаем.

## 5. Сценарии

1. **Подготовка к собеседованию.** Открыл сайт → выбрал раздел «DevSecOps и AppSec» → прочитал ответ про SAST → внизу увидел ссылку на OWASP → открыл её, страница живая.
2. **Поиск транслитом.** Нажал `/` → набрал «сием корреляция» → первым в выдаче вопрос про корреляцию событий в SIEM, слова подсвечены.
3. **Вопрос про право РК.** Нашёл вопрос о трансграничной передаче персональных данных → в ответе номер статьи закона → ссылка ведёт на действующую редакцию на adilet.zan.kz.
4. **Добавление вопроса.** Добавил запись в `content/NN-*.json` → `node scripts/build-corpus.mjs` → `npm test` зелёный → push → на живом сайте вопрос появился.

## 6. Не-цели

- DevOps_QA не правим, общий движок в библиотеку не выносим.
- Тесты-квизы, прогресс, карточки с интервальным повторением не делаем. Это другой продукт (есть Cyber Range Coach).
- Мультиюзер, авторизацию, бэкенд не делаем. Сайт статический.
- Английскую версию сейчас не делаем.
- Лабораторные и практику на стенде не делаем.

## 7. Доступы от человека

- **Создание публичного репозитория `Security_QA` на GitHub и первый push.** Это публикация от твоего имени, по правилам нужна явная «go». Альтернатива `[допущение]`: сначала приватный репозиторий без Pages, опубликовать позже.
- **Включение GitHub Pages в настройках репозитория** (Source, GitHub Actions). Одна галочка в интерфейсе GitHub, могу сделать через `gh` после твоего «go».
- `npm ci` в новом каталоге ставит те же пакеты, что уже стоят в DevOps-версии, по lock-файлу. Считаю это частью копирования, отдельно не спрашиваю.

## 8. Готово, когда

1. `npm test`, `npm run lint`, `npm run build` в `Security_Interview/` зелёные.
2. В корпусе 250 ± 10 вопросов по 9 разделам, у каждого непустой `sources`, тест это проверяет.
3. Все ссылки из `sources` отвечают кодом 200 (скрипт проверки ссылок, отчёт файлом).
4. Факт-чек пройден по всем 9 разделам, находки в `_factcheck/` закрыты, `fix-progress.json` показывает 100%.
5. Сценарии 1–3 проверены в браузере на локальном сервере, скриншоты сохранены.
6. `git -C ~/Desktop/Projects/DevOps_QA status` чистый, HEAD не сдвинулся.
7. После «go» на публикацию, сценарии 1–3 повторены на живом сайте Pages.
